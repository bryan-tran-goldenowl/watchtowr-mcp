What is the watchTowr MCP Server?

The watchTowr MCP Server connects AI assistants — such as Claude, Cursor, and other MCP-compatible tools — directly to your watchTowr Platform data.

Instead of switching between dashboards and chat windows, you can ask questions about your external attack surface in plain English and get real-time answers pulled straight from your watchTowr account.

It works through the Model Context Protocol (MCP), an open standard that lets AI assistants securely interact with external services. The MCP server acts as a bridge: your AI assistant sends a request, the server queries the watchTowr Platform API on your behalf, and returns the results in a format the assistant can reason about and present to you.

Key highlights:

  • 60 tools covering the full watchTowr Platform API
  • Read and write — query your attack surface and take action (update statuses, trigger retests, submit seed assets)
  • Composite intelligence — built-in tools for attack surface summaries, change detection, and security posture reviews
  • Secure — authenticates via your API key with tenant isolation; credentials never leave your environment

What Is It For?

The MCP server is designed to make your day-to-day work with the watchTowr Platform faster and more conversational. Here are some common use cases:

Get an instant attack surface overview

Ask your AI assistant for a summary and receive asset counts by type, finding counts by severity, and a snapshot of your overall posture — all in one response.

Triage findings through conversation

Instead of clicking through individual findings, ask questions like "show me all critical findings" or "what are the unresolved findings for business unit 5?" and get structured results you can act on immediately.

Track what changed this week

Use the built-in delta tools to see new assets and new findings discovered within any time window. Great for weekly security reviews or change monitoring.

Review hunt results and build remediation lists

Pull hunt details, see which findings a hunt produced, and generate remediation handoff lists with severity breakdowns and per-finding guidance.

Monitor certificates and services

Check for expiring certificates, cross-reference them with exposed services, and stay ahead of renewals before they become incidents.

Example prompts to try

  • "Give me an attack surface summary"
  • "Show all critical findings"
  • "What new assets were discovered this week?"
  • "List certificates expiring in the next 30 days"
  • "Show me suspicious domains flagged for typosquatting"
  • "Get the details for finding 1234 and trigger a retest"
  • "List all findings for business unit 5"
  • "What hunts have been completed recently?"
  • "What's the security posture for business unit 3?"
  • "Generate a remediation list for hunt 42"

How To Use It

Prerequisites

  1. A watchTowr Platform account with API access enabled.
  2. An API Key — obtained from your watchTowr Platform dashboard under Settings → API Management.
  3. Your Platform Host URL — your watchTowr instance URL (e.g. https://your-tenant.your-region.watchtowr.io).
  4. An MCP-compatible AI assistant such as Claude Desktop or Cursor.

Option 1: Docker (recommended)

The simplest way to run the MCP server. No local dependencies required beyond Docker.

For MCP clients (Claude Desktop, Cursor):

docker run -it --rm \
  -e WATCHTOWR_API_KEY="your-api-key" \
  -e WATCHTOWR_PLATFORM_HOST="https://your-tenant.your-region.watchtowr.io" \
  ghcr.io/watchtowr/watchtowr-mcp

As a standalone HTTP service:

docker run -d --rm \
  -e WATCHTOWR_API_KEY="your-api-key" \
  -e WATCHTOWR_PLATFORM_HOST="https://your-tenant.your-region.watchtowr.io" \
  -e MCP_TRANSPORT=streamable-http \
  -p 8080:8080 \
  ghcr.io/watchtowr/watchtowr-mcp

When using streamable-http transport, the server listens on port 8080 at /mcp.

Option 2: Local installation

For advanced users who prefer running natively. Requires uv (a Python package manager).

git clone https://github.com/watchtowr/watchtowr-mcp.git
cd watchtowr-mcp
git clone https://github.com/watchtowr/watchtowr-api-sdk.git

uv venv
uv pip install -e .
uv pip install -e watchtowr-api-sdk

WATCHTOWR_API_KEY="your-api-key" \
WATCHTOWR_PLATFORM_HOST="https://your-tenant.your-region.watchtowr.io" \
uv run watchtowr-mcp

Connecting your AI assistant

Once the server is running, configure your MCP client to connect to it. Below are configuration snippets for common clients.

Claude Desktop / Cursor (Docker)

Add this to your MCP client configuration:

{
  "mcpServers": {
    "watchtowr": {
      "command": "docker",
      "args": [
        "run", "--rm", "-i",
        "--env", "WATCHTOWR_API_KEY=your-api-key",
        "--env", "WATCHTOWR_PLATFORM_HOST=https://your-tenant.your-region.watchtowr.io",
        "ghcr.io/watchtowr/watchtowr-mcp"
      ]
    }
  }
}

Claude Desktop / Cursor (local)

{
  "mcpServers": {
    "watchtowr": {
      "command": "uv",
      "args": [
        "--directory", "/path/to/watchtowr-mcp",
        "run", "watchtowr-mcp"
      ],
      "env": {
        "WATCHTOWR_API_KEY": "your-api-key",
        "WATCHTOWR_PLATFORM_HOST": "https://your-tenant.your-region.watchtowr.io"
      }
    }
  }
}

Replace your-api-key and the platform host URL with your actual credentials. For the local option, update /path/to/watchtowr-mcp to where you cloned the repository.
